# mensetsu-report — 面接対策レポート

面接**前**に読む一枚のレポートを生成する。対話練習ツールではない（模擬面接は廃止済み）。
es-coach と同じ読み込み紀律（節の用途索引・部分読み・レジストリ解決）を共有する。

## パス解決（正本はレジストリ）

パスの**唯一の定義元**は `vault.paths.env`（clone 版はリポジトリ直下、plugin 版は `~/.config/shukatsu-skills/`。下の手順で解決する）。使うキー：

- `VAULT_SHUKATSU_CHISHIKI` → 蒸留知識（`全行業共通.md` / `金融.md` 等はこの配下）
- `VAULT_KIGYOU_REPORTS` → 企業分析报告（`/kigyou-report` が生成）
- `VAULT_SHUKATSU_SOZAI_SELF` → 素材/本人（経験インベントリ・grill 素材）
- `VAULT_SHUKATSU_ES` → 提出済み ES（会社別フォルダ）
- `VAULT_SHUKATSU_HIKAKU_LOG` → 添削ログ（ES添削＋過去の面接練習記録）
- `VAULT_MENSETSU_TAISAKU` → 面接対策（本 skill の保存先）

解決方法：

```bash
# vault.paths.env の場所は clone 版 / plugin 版で変わる。先頭から順に、最初に見つかったものを使う
for c in "${SHUKATSU_SKILLS_ROOT:-}/vault.paths.env" \
         "$HOME/.config/shukatsu-skills/vault.paths.env" \
         "${CLAUDE_PLUGIN_ROOT:-}/vault.paths.env"; do
  [ -f "$c" ] && { set -a; . "$c"; set +a; break; }
done
SKILLS_ROOT="${CLAUDE_PLUGIN_ROOT:-$SHUKATSU_SKILLS_ROOT}"   # tools/ の置き場
```

どれも見つからなければ、推測でパスを直さず「セットアップが未完了です。`$SKILLS_ROOT/setup.sh` を実行してください」と案内して終了する。

**本文にパスを直書きしない。パスが無ければレジストリを読み直す。**

## Step 1 — ヒアリング

確認する（IDE 選択範囲・会話文脈から拾えるものは聞かない）：
1. 企業名・**部門**（選択範囲から自動取得。同じ企業でも IBD と Operations では評価軸が全く違うため、部門の取り違えは致命的）
2. 面接段階（1次 / 2次 / 最終 / インターン選考）と形式（対面 / オンライン / HireVue録画 / スーパーデー）
3. 言語（日 / 英）
4. 面接日（わかれば。レポートの鮮度表示と当日チェックリストに使う）

## Step 2 — 読み込み（トークン紀律・必須）

**どのファイルも全読みしない**。合計 60k字以内を目安とする。

1. **`VAULT_SHUKATSU_CHISHIKI/全行業共通.md`**：冒頭の**「節の用途索引」表だけ**をまず読み、
   `用途` に `面接` または `共通` を含む節を選んで `grep -nE "^#{2,3} "` → `Read` offset/limit で部分読みする。
   `GD` は GD 選考があるときのみ。`ES`・`素材`・`情報戦` 専用の節は読まない。
2. **業界ファイル 1 件**（志望業界に一致するもの）：30k字未満なら全読、以上なら
   節の用途索引で `用途=面接/共通` ＋ `部門・業態` 列が志望部門に合う節だけ部分読み。
   形式が HireVue なら HireVue 節、該当企業の質問バンク節があれば必ず読む。
3. **企業分析レポート**（`VAULT_KIGYOU_REPORTS/【<企業名>】企業分析レポート.md`）：grep で 4 箇所だけ部分読み——
   志望部門の部門節／求める人材像の節／企業理念（`grep -n "理念\|パーパス\|Purpose"`）／
   面接・選考情報（`grep -n "面接\|選考プロセス\|想定質問"`）。レポートが無ければ「未作成のため企業固有情報は薄い」と断り、`/kigyou-report` を案内する。
4. **本人素材**：先に `$SKILLS_ROOT/tools/experience_inventory_sync.py` を実行 → `VAULT_SHUKATSU_SOZAI_SELF/経験インベントリ.md` を読む。
   grill 素材は frontmatter の `theme` で当たりを付けて関係分のみ。
5. **提出済み ES（最重要）**：`VAULT_SHUKATSU_ES/<会社名>/` 配下と、`VAULT_SHUKATSU_HIKAKU_LOG` の同一企業ログ
   （frontmatter `company_normalized` でマッチ）を読む。**面接の深掘りは提出 ES から来る**——ES に書いた内容・数字・
   エピソードとの整合が回答骨子の土台になる。
6. **過去の面接記録**：`VAULT_SHUKATSU_HIKAKU_LOG` の `面接練習_*` と `VAULT_MENSETSU_TAISAKU` の同一企業の過去レポートを
   frontmatter で当たりを付けて最大 2 件。前回露呈した弱点を「再発弱点ウォッチリスト」に引き継ぐ。

## Step 3 — レポート生成・保存

保存先：`VAULT_MENSETSU_TAISAKU/面接対策_<会社名略称>_<段階>_YYYYMMDD.md`

```markdown
---
date: YYYY-MM-DD
company: [正式名]
company_normalized: [英語正式名。添削ログと同じ正規化キー（Goldman Sachs / Morgan Stanley 等）]
department: [部門]
stage: [1次 / 2次 / 最終 / インターン]
format: [対面 / オンライン / HireVue / スーパーデー]
lang: [ja / en]
episodes_planned: [E1, E3]   # 回答骨子で使う予定のエピソードID（計画であり使用実績ではない）
weaknesses_watchlist: [過去記録から引き継いだ再発弱点キーワード]
outcome: 未定   # 面接結果が判明したら 通過 / 落選 / 辞退 に更新
outcome_date:
---

# 面接対策：[会社名]（[部門]・[段階]）

## 1. 面接概要と評価軸
[形式・時間・面接官構成（わかる範囲）。この段階で何が評価されるか——蒸留知識の段階別評価ポイント＋企業の求める人材像・理念を1段落で]

## 2. 想定質問バンク（優先度順）
| # | 質問 | 優先度 | 出典 |
[A=ほぼ確実に来る（定番＋企業固有バンク） / B=来たら差がつく / C=保険。各行に出典（蒸留知識§ / 企業レポート / 過去面接で実際に聞かれた）を明記]

## 3. 回答骨子（優先度 A の質問すべて＋Bの主要分）
### Q: [質問]
- **結論（一言）**：[最初に言う一文]
- **使うエピソード**：[E番号＋一行要約。ESに書いた内容と同じ数字・同じ事実関係を使う]
- **深掘り想定**：[この回答に対し面接官が刺してくる 2〜3 手と返し方]
- **ES との整合**：[提出ESの記述とズレやすい点。無ければ「—」]

## 4. 逆質問（3〜5案）
[蒸留知識の逆質問節の型 × 企業レポートの固有情報で組む。座談会で既に聞いた質問は使わない]

## 5. NG・当日チェックリスト
[段階・形式別の減点行動（外銀対面NG等）＋持ち物・接続確認。箇条書き 5〜8 個]

## 6. 再発弱点ウォッチリスト
[過去の面接練習・過去レポートで露呈した弱点。「前回〈記録名〉で〜が出た → 今回の対処」形式。初回なら「過去記録なし」]
```

保存後、`weaknesses_watchlist` と `episodes_planned` を frontmatter に必ず記録する（次回の横断参照用）。

## 行動ルール

- **ES との整合が最優先**：提出 ES と矛盾する回答骨子を作らない。ES に無い新エピソードを勧めるときは「ES未記載。深掘りで初出になる」と明示する
- **エピソードの偏りを警告**：経験インベントリで使用回数が多いエピソードは「この会社の ES でも使用済み——同じ話の繰り返しになるので別の切り口を用意」と指摘する。引き出しが足りなければ `/shukatsu-distill grill` を案内
- **企業固有の事実は裏を取る**：想定質問に織り込む企業情報（事業・数字・トップの発言）は、確証が無ければ WebSearch で確認してから書く。古い選考情報（面接形式・回数）は年度で変わる旨を注記する
- **蒸留知識は相関**：「内定者の体験談では〜が多い」の形で書き、断定しない
- **一枚で完結させる**：レポートを読めば追加の確認なしで面接に向かえる状態にする。ただし優先度 C まで骨子を書いて水増ししない——骨子は A 全部＋B 主要分まで
- **outcome を回収する**：同一企業の過去レポートに `outcome: 未定` があれば、冒頭で結果を一言確認して回填する（面接対策の精度検証はこの回填が頼り）
- **守備範囲**：ES 添削は `/es-coach`、本人素材の発掘は `/shukatsu-distill grill`、企業レポート作成は `/kigyou-report`。模擬面接（対話練習）は廃止済みで、求められたら本レポートの「深掘り想定」を使った自主練を案内する

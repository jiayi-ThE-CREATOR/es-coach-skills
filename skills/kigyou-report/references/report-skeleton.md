# レポートの骨格（書式サンプル）

**過去に生成したレポート本体を「書式の参考」として読まないこと**（1本 20〜46k字あり、書式を真似るためだけに読むには高すぎる）。書式はこのファイルだけで足りる。既存レポートの構成をどうしても確認したいときは、見出しだけを取る：`grep -n "^#\{2,3\} " <既存レポート>`。

以下は各要素の代表的な書き方。`<>` は埋める箇所。

## 冒頭（frontmatter 直後）

```markdown
# 【<企業名>】企業分析レポート

> [!success] 一言で言うと
> **<最も刺さる一文>**。<業界順位・代表的な数字（M&A ランキング、シェア等）>、社風は「**<一言>**」。新卒初任給 <数字>、<選考の特徴>。**<採用方式（部門別/一括）>**で、内定難易度は<位置づけ>。

> [!tip] このレポートの使い方
> 1. **会社概要〜部門マップ**で全体像を掴む
> 2. **採用フロー・求める人材像**で戦略を立てる
> 3. **ES・面接対策**を実戦で使う
> 4. 競合（[[<競合ノート名>]]）と必ず比較する

---
```

## テーブル（会社概要・年収・競合比較など）

```markdown
## 1. 会社概要

| 項目 | 内容 |
|------|------|
| 正式名称 | <> |
| 設立（日本） | <> |
| 親会社 | <> |
| 日本における代表者 | <> |
| 従業員数（日本） | <>（推定なら「推定」と明記） |
| 主要事業 | <> |

> [!info] <補足の見出し>
> <公式情報に基づく補足。数字は裏取り済みのものだけ>
```

## 引用（理念・求める人物像・部門説明）

```markdown
> [!quote] 公式（<ドメイン> / <ページ名>）
> **<原文をそのまま。英語ソースは英語のまま>**
```

## 注意喚起

```markdown
> [!important] <最新動向の見出し>
> <直近の組織変動・採用変更など、年度で変わる情報>

> [!danger] <致命傷の見出し>
> <これをやると落ちる、という具体的な行動>
```

## Mermaid（採用フロー・昇進フロー・準備プラン）

採用フローは `flowchart LR`、キャリアパスは `flowchart TB`、準備プランは `gantt`。
部門概観図は 3 層構造で、テンプレは `division-section.md` にある。

## フッター（セクション 12 の後）

```markdown
## FAQ

> [!question] <よくある疑問>
> <回答>

## 関連ノート

- [[<実在を確認したノート名>]]

## 情報源

- <公式ページ名>（<URL>、取得日 YYYY-MM-DD）
- <記事名>（媒体名、YYYY-MM-DD）

> [!note] メンテナンス
> 採用フロー・年収は年度で変わる。<次に確認すべき時期>に再確認すること。
```

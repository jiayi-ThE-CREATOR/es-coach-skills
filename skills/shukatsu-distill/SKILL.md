# shukatsu-distill — 就活知識蒸留・素材化ツール

日本就活の内定者経験談を蒸留し、下流（/es-coach＝ES添削、/mensetsu-report＝面接対策）の知識ベースを作るスキル。

## パス解決（正本はレジストリ）

パスの**唯一の定義元**は `vault.paths.env`（clone 版はリポジトリ直下、plugin 版は `~/.config/shukatsu-skills/`。下の手順で解決する）。vault 再編成時もそこだけ更新すればよい。対応キー：

```
VAULT_SHUKATSU_DISTILL    → 就活蒸留システムの根目録（素材/蒸留知識/添削ログの共通の親）
VAULT_SHUKATSU_SOZAI_YT   → 素材/YouTube/
VAULT_SHUKATSU_SOZAI_WEB  → 素材/就活サイト/
VAULT_SHUKATSU_SOZAI_SELF → 素材/本人/（grill モードの保存先）
VAULT_SHUKATSU_CHISHIKI   → 蒸留知識/内定之路/（成功パターン .md はこの配下）
VAULT_SHUKATSU_HIKAKU_LOG → 添削ログ/
VAULT_INBOX               → （任意）自動収集候補の置き場。review モードが `蒸馏候補_*.md` を探す
```

**以降の手順に出てくるパスが存在しなかったら、ここを推測で直すのではなくレジストリを読んで解決し直すこと。**

## モード選択

引数を確認する：
- `ingest` → ingestモードへ
- `distill` → distillモードへ
- `coach` → 廃止案内（coach モード参照）
- `grill` → grillモードへ（逆面接で本人の頭の中から素材を抽出する）
- `review` → reviewモードへ（自動収集された候補を複核し、採用分だけ素材にする）
- `log` → logモードへ（本人の選考結果・実際に聞かれた質問を記録する）
- 引数なし → ユーザーにどのモードか確認する
- ES添削は `/es-coach` スキルを案内する

---

## ingest モード

**目的**: 経験談・動画文字起こし・就活サイト記事を素材として保存する。

### 手順

**Step 1 — 素材の受け取り**

ユーザーが提供するものを確認する：
- テキスト貼り付け → そのまま使用
- URL（YouTube / 就活サイト / Unistyle / 外資就活 / Voluntas等）→ defuddleスキルでMarkdown抽出を試みる。失敗した場合はWebFetchで直接取得する
- **会員限定のページ**（外資就活の体験記・ONE CAREER・Alternative Careers 等。本文の途中で「会員登録して続きを読む」になる）→ 下の「会員限定ページの取得」に従う
- **本人が書いた説明会・座談会のノート**（素材フォルダの外にあるもの）→ 下の「本人ノートのポインタ型素材」に従う

**会員限定ページの取得**
1. **パスワードを会話に書かせない**（会話記録に残る）。代わりに、ブラウザ自動化ツール（Playwright / patchright 等）で**専用の使い捨てプロファイル**を使い、**画面付きのブラウザ窓を開いてユーザー本人にログインしてもらう**。ユーザーが窓を閉じたらログイン状態がプロファイルに残る
2. 同じプロファイルで対象ページを開き、本文テキストを取得する。一覧ページからは個別ページの URL を拾い、**卒年・部門で絞ってから**取得する（全件は取らない）。**数秒間隔**で取得し、サーバーに負荷をかけない
3. ナビゲーション・募集広告・フッターを取り除いてから読む
4. サイトは無断転載禁止が多い → 素材には**本人の学習用に要点を整理**して保存し、全文の複製はしない。質問文・数値・本人コメントは原文の表現を残してよい
5. 取得が終わったら**プロファイル（ログイン状態）を削除するようユーザーに勧める**（自動では消さない。削除はユーザーの判断）

**本人ノートのポインタ型素材**
- 本人が vault の別の場所に書いた説明会ノート等は、**本文を素材フォルダに複製しない**（2つのコピーは必ず食い違う）。素材ファイルには frontmatter・**原文ノートへのリンク**（`source: "[[ノート名]]"`）・**他社にも使える一般化できる要点**だけを書く
- 会社固有の数字・組織名・案件は原文ノートと企業分析レポートに残す
- ノートに「CONFIDENTIAL」「外に出さない」等の表記があれば、素材にもその旨を書く。**vault の外（公開リポジトリ・外部サービス）には出さない**
- ingest のたびに、本人ノートの置き場に**まだ素材化していない説明会ノートが無いか**を確認し、あればユーザーに素材化するか聞く（一次情報は最優先の素材）

**Step 1.5 — 重複チェック**（URLが提供された場合のみ）

以下のコマンドで既存ファイルに同じURLが存在しないか確認する：

```bash
# 上の「パス解決」の手順で vault.paths.env を読み込んでおくこと
grep -rl "source: [入力されたURL]" "$VAULT_SHUKATSU_DISTILL/素材/"
```

既存ファイルが見つかった場合：「このURLはすでに `[ファイル名]` として保存されています。再ingestionしますか？」と確認してから続ける。

---

**Step 2 — メタデータ抽出**

素材から以下を読み取る（不明な場合は「不明」と記載）：

```
- 内定先: [企業名・業界]
- 業界分類: [金融 / 商社 / コンサル / IT / 全行業共通 / 複合]
- ソース種別: [YouTube / 就活サイト / その他]
- ソースURL: [あれば]
- 内定数: [何社か記載があれば]
- 就活時期: [何年度か]
```

**Step 3 — 業界分類の判定**

素材の主な対象を判定する：
- 外資投資銀行・証券・メガバンク・信託・保険 → `金融`
- 総合商社・専門商社 → `商社`
- 戦略コンサル・総合コンサル・会計系アドバイザリー（McK / BCG / PwC / デロイト等）→ `コンサル`
- IT（ハードウェア / ソフトウェア / インターネット・Web / 通信インフラ / 情報処理サービス・SIer）→ `IT`
- エンジニア職（技術面接・研究/開発の説明・技術選定・コーディング面接など**職種**としての選考）→ `エンジニア`。業界を問わない（IT企業・金融機関のIT部門・SIer の技術職すべて）。業界研究（どの領域・どの会社か）は `IT`、職種としての選考は `エンジニア` に分ける。両方含む素材は `複合`
- 複数業界にまたがる / 就活全般のコツ → `全行業共通`
- 複数業界にまたがる → `複合`（該当業界すべてにタグ付け。例：金融×IT の証券システム／SE 系）

`industry` には**上の7つの値（金融 / 商社 / コンサル / IT / エンジニア / 全行業共通 / 複合）のどれか1つだけ**を書く。「金融（外資 IB）」のような細分を書きたいときは、別の項目 `segment:`（例：`segment: 外資証券・Operations`）に書く。industry の値がばらけると、業界別の集計と振り分けが壊れる。

**Step 4 — ファイル保存**

保存先を決定する：
- YouTube動画の文字起こし → `素材/YouTube/`
- 就活サイト記事・ブログ → `素材/就活サイト/`

ファイル名: `YYYY-MM-DD_[内定先略称]_[業界].md`
例: `2026-05-08_三菱商事_商社.md`

ファイル内容フォーマット：
```markdown
---
title: [タイトル or 動画タイトル]
source: [URL or "貼り付け"]
source_type: [YouTube / 就活サイト / その他]
industry: [金融 / 商社 / コンサル / IT / エンジニア / 全行業共通 / 複合]
company: [内定先]
offer_count: [内定数 or 不明]
year: [就活時期 or 不明]
added: YYYY-MM-DD
distilled: false
---

# [タイトル]

## 原文・要約

[素材の全文 or 要約（できるだけ原文を保持）]

## 抽出メモ（ingest時点の速報）

[明らかに重要だと思った点を3〜5点箇条書き]
```

**Step 5 — 報告**

以下を報告する：
- 保存パス
- 業界分類
- 速報メモ（3点）

**Step 6 — 自動蒸留＋状態報告（必須・ユーザーの恒久指示）**

ユーザーから「素材を追加したら毎回 蒸留知識を同期し、更新の有無とフォルダが最新状態かを報告せよ」という恒久指示がある。
したがって素材保存後、**確認を取らずに続けて distill モードを実行**する（複数素材をまとめて ingest した場合は全部保存し終えてから1回 distill する）。
distill 完了後、必ず次の2点を明示する：
- **今回の更新**：あり（更新した知識ファイル名＋追記パターン数）／ なし（新規の未蒸留素材なし）
- **蒸留知識フォルダの状態**：✅ 最新データに基づく（未蒸留 0 件）／ ⚠️ 未蒸留 N 件残（ファイル名）

---

## distill モード

**目的**: 素材フォルダの全ファイルを分析し、成功パターンを蒸留知識ファイルに反映する。

### 手順

**Step 1 — 未蒸留素材の確認**

以下のコマンドで `distilled: false` のファイルを先に特定する：

```bash
# 上の「パス解決」の手順で vault.paths.env を読み込んでおくこと
grep -rl "distilled: false" "$VAULT_SHUKATSU_DISTILL/素材/" 2>/dev/null
```

素材ルート全体を探索する（`就活サイト/` `YouTube/` `一次情報/` `本人/` `ES_長所短所/` `其他/` すべて対象）。
このコマンドの結果リストのファイルのみを読み込む（全ファイルを読まない）。

あわせて**自動収集候補の未複核分**も確認する（`VAULT_INBOX` が定義されている場合）：
```bash
grep -l "^distilled: false" "$VAULT_INBOX"/蒸馏候補_*.md 2>/dev/null
```
1件以上あれば、distill の前に「未複核の候補が N ファイルあります。review しますか？」と聞く。候補は素材ではないので、**review を通さずに蒸留知識へ直接入れない**。

未蒸留素材が0件なら「新しい素材がありません」と報告して終了（未複核の候補があればその件数も添える）。

**Step 2 — 既存の蒸留知識を読む**

更新対象ファイルを読み込む（実体は `VAULT_SHUKATSU_CHISHIKI` 配下）：
- `全行業共通.md`
- `金融.md`（金融素材があれば）
- `商社.md`（商社素材があれば）
- `コンサル.md`（コンサル素材があれば）
- `IT.md`（IT素材があれば）
- `エンジニア.md`（エンジニア職素材があれば。職種ファイル）

**Step 3 — パターン抽出（核心）**

未蒸留素材を読み込み、以下の観点で分析する：

**全行業共通で見るべき観点：**
- 第一印象・声・態度に関する言及
- 自己PR・ガクチカの構成パターン（STAR法など）
- 志望動機の組み立て方
- 面接での話し方・テンポ・論理展開
- 「落ちた人と何が違った」という自己分析
- 準備の量・質（模擬面接回数、OB訪問数など）
- 面接官が「刺さった」と言った瞬間

**金融特有で見るべき観点：**
- 金融を志望した動機の説得力
- 市場・財務知識の水準
- 外資と国内の違いへの理解
- 「お金を扱う」職業への適性をどう示したか
- 面接で問われた数字・ケース問題

**商社特有で見るべき観点：**
- ガクチカのスケール感と選び方
- 主体性・リーダーシップのエピソード型
- 海外・異文化経験の使い方
- 「なぜ商社か」「なぜこの商社か」の差別化
- GD・ケース面接での振る舞い

**コンサル特有で見るべき観点：**
- 「なぜコンサルか」「なぜ戦略/総合/会計系か」の差別化と論理性
- ケース面接・フェルミ推定への準備方法と実際の出題
- 構造化思考・仮説思考をエピソードでどう示したか
- 激務・Up or Out への覚悟をどう伝えたか
- 他業界（投行・商社）併願をどう説明したか

**IT特有で見るべき観点：**
- 5領域（ハード / ソフト / Web / 通信インフラ / SIer）のどこを志望し、なぜその領域かの言語化
- 「なぜITか」「なぜSIerか（自社開発でなく受託か、その逆か）」の差別化
- 技術への興味と、文系でも通用する論理性・課題解決の示し方
- 個社の稼ぎ頭がどの領域か（売上構成）を踏まえた企業研究の深さ
- 金融×IT（証券・銀行システム、勘定系・トレーディング）志望なら、SIerと金融機関システム部門の違いの理解

**エンジニア職特有で見るべき観点**（`エンジニア.md` へ。業界研究は `IT.md` へ）：
- 面接で実際に聞かれた技術質問の言い方と、続く深掘り（例：「なぜその技術？」→「今ならどう選ぶ？」）
- 研究・開発を非専門家向け／専門家向けに説明する型と、評価された水準
- 技術選定・設計判断の語り方（代替案・トレードオフ・計算量・拡張性）
- コーディング面接・システムデザイン・行動面接の形式と対策期間
- AI活用・学習習慣・アウトプット（GitHub・記事・競プロ）がどう評価されたか
- 新しい質問が出たら `エンジニア.md` の「面接質問バンク」節に、問い方・観点・深掘り・高評価の答え方の形で追記する

**Step 4 — 蒸留知識の更新**

各知識ファイルの該当セクションに、抽出したパターンを追記する。

書き方のルール：
- **上書きしない**、既存の内容に追記する
- パターンは「〜という傾向がある」「〜と言っている人が多い」という形で書く
- 素材の出典を`[出典: ファイル名]`の形で括弧内に入れる
- 矛盾するパターンは削除せず「一方で〜という見方もある」と併記する
- 数が増えたら冒頭のsource_countを更新する

**情報の重み（一次 > 体験記 > 二次）**：
- 採用側が自分の口で説明した一次情報（説明会スライド・採用担当の講義）＞ 受験者の体験記（選考の実態）＞ 就活塾・まとめ記事・自動抽出の候補（二次情報）
- 二次情報を書くときは節の冒頭に「二次情報」と明記し、上位の情報と矛盾したら上位を優先すると書く

**鮮度（古い情報の扱い）**：
- 選考の形式・回数・質問は年度で変わる。追記するパターンには**素材の卒年・年度**が分かるようにする（出典名に年が入っていなければ「（26卒）」等を添える）
- 同じテーマで**新しい素材が古い記述を上書きする内容**なら、古い記述は消さずに直後へ「**更新（YYYY 年度・出典）**：…」を足し、古い方に「年度差として扱う」と書く。消費側は更新の方を優先する

**会社固有の事実と、一般化できるパターンの分け方**：
- 会社の組織・数字・案件・制度などの**固有の事実**は、企業分析レポート（`/kigyou-report`）か本人ノートに置く。蒸留知識には「その会社の例では〜」と短く引用するか、リンクだけにする
- 選考の形式・実際の質問・評価軸は、他社の受験者にも使えるので蒸留知識に置いてよい。ただし**個社ごとの節は1つの母節（例：「各ハウスの個社選考」）の下にまとめ**、業界ファイルの本文を個社の話で埋めない
- 業界ファイルが大きくなりすぎたら（目安：日本語 15 万字超）、業態での分割を検討する。分割するときは、消費側（`/es-coach`・`/mensetsu-report`）が業界ファイルを一覧で拾う仕組みとの整合を先に確認する

**落ちた例（負例）の集約**：
- 落ちた ES・面接の実例や本人分析を追記したら、その業界ファイルの「落ちた人との差分」節に**どこに何があるかの1行**を足す。負例は散らばると誰にも読まれない

**節を新設・改番・削除したら「節の用途索引」を同じ蒸留で必ず更新する（必須）**：
`全行業共通.md` と `金融.md` は冒頭に `## 節の用途索引（ルーティング表・自動更新）` を持つ。これは消費側（`/es-coach`＝ES添削、`/mensetsu-report`＝面接対策レポート）が**全読みを避けて必要な節だけ部分読みするための単一の正**。
- 節を**新設**したら索引に1行足す。`用途`（`共通`/`ES`/`面接`/`GD`/`WEBテスト`/`素材`/`情報戦` から該当するもの）、`ES設問タイプ`（`ES`か`共通`を含む節のみ。ガクチカ/自己PR/志望動機/長所短所/失敗・挫折/全設問）、金融は `部門・業態`（部門で読み分ける節のみ。`—`＝部門不問）を埋める。
- 節を**改番・改名**したら索引の該当行を直す。**節番号を消費側が持たず索引だけを見る設計なので、索引を直し忘れると新知識が誰にも読まれない**（最悪の失敗モード）。
- 面接寄りの節に ES に効く小節が混じる場合は、索引で `└ 11.4 …` のように小節を切り出して用途を分ける。
- 索引を持たない業界ファイル（IT/エンジニア/コンサル/商社。いずれも 30k字未満で消費側は全読）は、**30k字を超えたら** この索引表を新設し消費側に「索引あり」を知らせる。

更新後、素材ファイルの `distilled: true` に変更する。

**Step 5 — 蒸留サマリーの報告**

以下を報告する：
- 処理した素材数
- 各知識ファイルに追加されたパターンの件数
- 今回の蒸留で見つかった最も重要なインサイト（上位3点）
- 知識ファイルへのパス
- **状態確認（必須）**：Step 1 の grep を再実行して `distilled: false` が 0 件かを確認し、
  「✅ 蒸留知識フォルダは最新データに基づく（未蒸留 0 件）」/「⚠️ 未蒸留 N 件残（ファイル名）」を明示する。
  あわせて「今回の更新：あり／なし」も1行で述べる。

## review モード — 自動収集候補の複核

**目的**: 自動巡回（YouTube・RSS 等から LLM で抽出）された「成功パターン候補」を複核し、**採用するものだけ**を素材にする。候補は無人で作られるので、そのまま蒸留知識に入れると知識ベースが汚れる。

### 手順

**Step 1 — 未複核の候補を集める**
```bash
grep -l "^distilled: false" "$VAULT_INBOX"/蒸馏候補_*.md 2>/dev/null
```
件数が多いとき（数百件）は全文を読まず、**候補1件＝1行（日付・業界・タグ・主張・出典）の一覧**に抜き出してから読む。

**Step 2 — 既存の蒸留知識と照合する**
主要な語句を `grep` して、既に蒸留知識にある内容かを確かめる（重複は採用しない）。

**Step 3 — 採用・不採用を決める**

不採用にするもの：
- **企業の採用 PR の言い換え**（「〜をアピールする企業は〜の傾向がある」型）
- 本人の選考に関係しない日程・参加資格の話（例：受けない採用イベントの手続き）
- 既存の蒸留知識と同じ一般論（「主体性が評価される」等）
- 講座・サービスへの誘導

採用するもの：
- 具体的な質問・課題・評価軸・NG の型など、**ES や面接でそのまま使える**もの
- 既存の知識と**食い違う**もの（併記する価値がある）
- 複数の出典で同じことが言われているもの（信頼度が上がる）

**Step 4 — 採用分を1つの素材ファイルにまとめる**

保存先：`素材/其他/YYYY-MM-DD_蒸留候補複核_[期間]_採用分.md`。frontmatter は ingest と同じ形（`source_type: その他`、`industry: 複合` 可）。本文は業界ごとに「主張｜出典記事のタイトル（候補日）」の形で書き、冒頭に**複核の方針・採用率・不採用の理由・出典の信頼度**を書く。

**Step 5 — 候補ファイルに複核済みの印を付ける**

各候補ファイルの frontmatter を `distilled: true` にし、`reviewed: YYYY-MM-DD（複核済み。採用分は [素材ファイル名]）` の行を足す。

**Step 6 — distill を実行する**（ingest Step 6 と同じ恒久指示）

採用分の素材は二次情報として蒸留する（distill Step 4 の「情報の重み」に従う）。

## log モード — 本人の選考結果の記録

**目的**: 本人の選考結果（通過・落選）と、**実際に聞かれた質問・使ったエピソード・詰まった箇所・手応え**を残す。蒸留知識は他人の成功パターン（負例を含まない相関）なので、**本人の負例はここでしか手に入らない**。`/mensetsu-report` の「再発弱点」の材料になる。

**使うタイミング**: 面接・選考の**直後（24時間以内）**。結果が出たら同じファイルに追記する。

### 手順

**Step 1 — 聞き取る（1問ずつ、短く）**

- 会社・部門・段階（ES／テスト／録画／一次〜最終／インターン）・形式（人数・時間・言語）
- **実際に聞かれた質問**（できるだけ原文。深掘りの流れも）
- 使ったエピソード（同じ選考の中で**同じエピソードを何回使ったか**も）
- 詰まった・言い淀んだ質問、想定外だった質問
- 手応え（1〜5）
- 結果（後日でよい）と、通過・落選の理由だと思うこと

既存の面接対策ファイルや録画面接の実測メモがあれば、先に読んで重複して聞かない。

**Step 2 — 保存する**

保存先：`VAULT_SHUKATSU_SOZAI_SELF`（素材/本人/）。ファイル名：`選考ログ_[年度]_[会社や選考群].md`（同じ会社・同じ時期の選考は1ファイルに追記）。

```markdown
---
title: 選考ログ — [会社・部門]
source: 本人の選考記録
source_type: 本人
industry: [金融 / 商社 / コンサル / IT / エンジニア / 全行業共通 / 複合]
segment: [部門]
theme: 選考結果ログ
added: YYYY-MM-DD
distilled: false
---

# 選考ログ — [会社・部門]

## 結果一覧（表：会社・部門／各段階の結果／最終結果／判明日）

## [会社] — [段階]（日付）
- 形式：
- 実際に聞かれた質問：
- 使ったエピソード：
- 詰まった箇所・想定外：
- 手応え：
- 結果：
- 理由の仮説：（本人の言葉。Claude の観察は「仮説・要本人確認」と書き分ける）
```

本人がまだ答えていない項目は「【本人記入】」として空欄で残す（推測で埋めない）。

**Step 3 — distill を実行する**

本人の負例は、業界ファイルの「本人の選考ログ — 再発パターン」節（無ければ新設し索引に足す）と「落ちた人との差分」節の1行に反映する。**事実（結果・実際の質問）と仮説（理由）を分けて書く**。仮説は本人の振り返りが入ったら事実で置き換える。

## coach モード

模擬面接（coach mock）は**廃止**。面接準備は対話練習ではなく `/mensetsu-report`（面接対策レポート）で行う。

- `coach` / `coach mock` と言われたら → 「模擬面接は廃止しました。面接対策レポート `/mensetsu-report` をお使いください」と案内して終了
- ES添削の要求 → `/es-coach` スキルを案内して終了

## grill モード — 逆面接（知識抽出）

**目的**: ユーザーの頭の中にしかない経験・価値観・エピソードを、AI からの集中質問（15〜30問）で掘り出し、蒸留システムの素材として保存する。内定者パターン（蒸留知識）は「他人の成功」、grill は「本人の原石」——両方揃って初めて ES・面接の個別戦略が組める。

### 手順

**Step 1 — テーマ設定**

ユーザーに一つ選ばせる（または指定を受ける）：
- `自己分析` — 価値観・強み弱み・人生の転機
- `ガクチカ深掘り` — 1つのエピソードを面接官視点で掘り尽くす
- `志望動機` — Why 金融/商社・Why この会社・Why あなた の接続を固める
- `弱点つぶし` — 想定問答で答えに詰まる質問を先に洗い出す

**Step 2 — 蒸留知識の事前読み込み**

`VAULT_SHUKATSU_CHISHIKI` 配下の該当業界ファイルを読み、内定者パターンとのギャップを突く質問を設計する（例：内定者は挫折経験を定量化して語る傾向→「その失敗、数字で言うとどれくらいの損失？」）。

**Step 3 — 逆面接の進行**

- **1問ずつ**。回答を受けてから次を出す。安易に納得しない：抽象的な回答には「具体的には？」「固有名詞で言うと？」「そのとき何を感じた？」「なぜそうした？」と最低1段は掘る
- 良い素材（数字・固有名詞・感情の動き・因果・意外性）が出たら「📌 素材として記録」と宣言して控える
- 15問を超えたあたりで「続けるか、ここまでの分を保存するか」を確認する
- ユーザーが「終わり」「ここまで」と言ったら Step 4 へ

**Step 4 — 素材ファイル保存**

保存先：`VAULT_SHUKATSU_SOZAI_SELF`（素材/本人/）
ファイル名：`YYYY-MM-DD_grill_[テーマ].md`

```markdown
---
title: grill セッション — [テーマ]
source: grill（逆面接）
source_type: 本人
industry: [金融 / 商社 / コンサル / IT / エンジニア / 全行業共通]
theme: [テーマ]
added: YYYY-MM-DD
distilled: false
---

# grill — [テーマ]（YYYY-MM-DD）

## 抽出された素材（Q&A 形式、本人の言葉をできるだけ原文保持）

### Q1: [質問]
[回答の要点＋本人の表現]

…

## セッション所見

- ES・面接にそのまま使える発見: …
- 内定者パターンとのギャップ: …
- まだ掘れていない領域（次回の grill 候補）: …
```

**Step 5 — 自動蒸留＋状態報告（ingest Step 6 と同じ恒久指示）**

保存後、確認を取らずに distill モードを実行し、「今回の更新あり/なし＋蒸留知識フォルダの状態」を報告する。本人素材は `[出典: grill_ファイル名]` として蒸留知識に追記される——内定者パターンと本人の実体験が同じ知識ベースで突き合わせ可能になる。
